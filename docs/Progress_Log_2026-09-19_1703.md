## 5. The bootstrap was biased — found while previewing `p_top20`

User asked why build a top-20 probability output. A scratch preview of it (score
matrix kept from the same bootstrap) gave implausible results: Chin Bee (point
rank 8) 4% to stay, Gul Circle 1%. Investigation:

- **Bias**: the saved bands had the point estimate ABOVE its own p95 for 31 of
  332 subzones (8 of the top 20) — e.g. Little India point 0.842 vs band
  0.721–0.814. Cause: `build_score` re-min-maxes every noisy draw, so noise
  stretches the exposure range and squashes hot subzones' normalised scores.
- **Noise level**: with the bias removed (fixed scale), the exposure noise —
  NEA-heldout RMSE 11.64 °C — was mostly the *systematic* Landsat-vs-air-
  temperature offset, not random error, and swamped the real spread between
  subzones (native30 std across subzones 2.49 °C): noise alone replaced ~16.5
  of the top 20. The old narrow bands (0.103) had been hiding this.
- **Candidates** (native30 minus held-out): NEA n=12 offset +11.38, RMSE 11.64,
  offset-removed std 2.55; MODIS n=329 offset +6.13, RMSE 6.51, std 2.17. A
  constant offset can't move a rank (min-max cancels it), so the offset-removed
  spread is the right noise. Scenario table (fixed scale): MODIS 2.17 → width
  0.199, 19/19, replaced 9.8; NEA 2.55 → 0.251, 11.0; greenery-noise only (floor)
  → 0.051, 3.6.

User: "go". **Implemented (commit `d2d1b74`)**: `normalize(..., ref=)` and
`build_score(..., reference_df=)` pin the bootstrap's scale;
`exposure_noise_std` = offset-removed residual std; new
`config.settings.EXPOSURE_NOISE_SOURCE = "modis"`; `p_top20` column in the bands
CSV; shown as a colour option on the Island Map, a metric on Subzone Breakdown
and in the dashboard's S6 section; module docstring rewritten with the stated
limitations (sensitivity unperturbed, exposure noise is an upper bound, greenery
noise rough, not statistically calibrated). Old bands backed up to
`_backup_pre_bootstrap_fix_2026-09-19/`.

Result on real data: mean band width 0.199, **0/332** outside own band (was
44), 19/19 adjacent overlaps, top-20 probability tiers (≥0.9 / 0.5–0.9 / <0.5)
0/10/10, expected replaced by noise 9.8. The repo run reproduced the scratch
scenario numbers exactly.

Tests (`tests/test_confidence_bands.py` → 8 checks): a bias regression test
(median shift 0.0042 with the fix vs 0.0350 with the old behaviour on the same

std and `reference_df` properties. **Fixture lesson**: independent random pillars
give mixed-sign PCA loadings and blow scores up, so a normalisation test must use
equal weights (or positively-correlated pillars).

## 6. Settling the two "open limitations" (scratch analysis, then a correction)

**Adaptive-capacity noise.** A constant misclassification rate is an affine map
of true greenery (recall 0.913, false-positive rate 0.349 → observed ≈ 0.35 +
0.56·true); min-max normalisation cancels it exactly (max score change 4.4e-16,
top-20 overlap 1.0). Only per-subzone *heterogeneity* of error can move a rank,
which a global recall SE never measured. Empirical proxy: hybrid-vs-NDVI-proxy
residual std 0.0644 (R² 0.921), 2.3× the 0.0276 — but bands only 0.199→0.218 and
top-20 replaced 9.8→10.4, so it is immaterial next to exposure noise.

**Sensitivity pillar.** Not measurement noise (SingStat counts are near-exact) —
it is *formula* uncertainty. With the then min-max PCA: weights/definition
variants moved 3–5 of the top 20, but density-instead-of-count moved 19.

**Correction (same day).** That 19-of-20 was mostly a **PCA scaling artefact**:
`build_score` ran PCA on min-max pillars, so weights followed each pillar's
*spread* (std of the min-max sensitivity pillar 0.169 with count vs 0.288 with
density → PCA weight 0.16 vs 0.45) while its correlation with the other pillars
was ~0.2–0.3 either way. Two of my own hypotheses were wrong — count is not
confounded with subzone size (Spearman 0.00), and density is not more redundant
with the heat pillars. PCA on z-scored pillars: weights stable (0.38/0.23/0.39
count vs 0.37/0.23/0.40 density); PCA-vs-equal collapses from 10 to 4.
