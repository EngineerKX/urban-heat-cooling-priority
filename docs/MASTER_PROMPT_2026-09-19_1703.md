## What this project is

NUS-ISS Practice Module (Graduate Certificate in Pattern Recognition Systems). A
pattern-recognition system that fuses Landsat thermal + Sentinel-2 multispectral +
Singapore open geospatial/demographic data into a validated, calibrated
**cooling-priority score per URA planning subzone** (332 subzones) — decision
support for prioritising urban cooling interventions. Positioned explicitly against
Cooling Singapore's UHV work (cited as related work, **not** claimed as an empty gap
— don't write "first" or "no one has").

Seven pipeline stages, all built: **S1** ingest/composite, **S2** LST downscaling,
**S3** land-cover classification (RF + U-Net **hybrid**), **S4** unsupervised hotspot
clustering, **S5** predictive heat model with counterfactuals (XGBoost + CNN), **S6**
cooling-priority score with confidence bands, **S7** the Streamlit system.

**Two framings of the contributions exist — know which one a doc uses.**
- *Proposal framing (C1–C4, every doc up to 2026-09-18)*: C1 data-driven (PCA) weighting
  vs an equal-weight baseline; C2 a learned predictive heat model enabling counterfactual
  queries; C3 multi-sensor LST downscaling (30 m → 10 m); C4 season-controlled composites.
- *Reframed (the user's wording, 2026-09-19)*: evidence-based prioritisation,
  confidence-informed prioritisation, decision-focused evaluation, resolution-aware
  planning; novelty = integrated workflow + planning-impact focus. Rough mapping: #1 ≈ C1;
  #4 ≈ C3; #2 and #3 are new framing over the S6 bands and the rank-impact tooling; C2 is
  a "planning check" under the integrated-workflow novelty; C4 is the data foundation.

> **Contributions** — *Evidence-based prioritisation:* Uses data-derived weights to identify where cooling interventions are most needed. *Confidence-informed prioritisation:* Estimates how stable and reliable the priority rankings are under measurement uncertainty. *Decision-focused evaluation:* Evaluates whether methodological choices and model improvements actually change planning priorities. *Resolution-aware planning:* Examines whether higher-resolution heat maps change which subzones are prioritised.
>
> **Novelty** — *Integrated workflow:* Combines heat estimation, confidence assessment, prioritisation, and planning evaluation in one workflow. *Planning-impact focus:* Evaluates technical improvements based on whether they meaningfully affect planning decisions.
>
> **Context:** The approach is applied at the URA subzone level in Singapore, making the results relevant to practical urban planning.

## Conventions to know before touching this code

Everything from prior snapshots still holds (`config/settings.py` is the only place constants
live; placeholder formulas marked not resolved; no pytest — tests are runnable scripts;
`scripts/` never import from each other; channels-last / `.keras`; "hybrid" not "ensemble").
**New this session:**

- **A retrain does NOT auto-invalidate downstream outputs.** The adaptive pillar, bands,
  hotspot and XGBoost scripts only check that their output exists. Refresh order after a
  retrain / land-cover rebuild: adaptive pillar `--force` → `build_priority_score.py` (no cache)
  → bands `--force` → hotspots (move the two output CSVs aside; `--force` would also re-fetch
  land-cover-independent GEE features) → XGBoost `--force-retrain` → `diagnose_heat_model.py`;
  `build_landcover_swap_comparison.py` recomputes by itself (modified-time check). Back up
  `data/processed` first — old-vs-new is itself a model-change stability result.
- **Never re-normalise a noisy draw against its own range** (bootstrap bias); use
  `build_score(..., reference_df=df)`.
- **PCA weights are fitted on z-scored pillars**; fitting on min-max pillars makes them follow
  each pillar's spread, not its information. A standardised PCA gives an uninformative pillar
  ~zero weight and is blind to a pillar's direction (loadings are sign-aligned).
- **Report offset, spread and Spearman — not RMSE** — when comparing to a held-out LST source
  (`rank_impact.heldout_agreement`).
- **Test fixtures**: independent random pillars give mixed-sign, unstable PCA loadings — use
  `weighting="equal"` for a non-PCA property, or positively-correlated pillars; calibrate a
  regression test's threshold against the old buggy behaviour so you know it would have failed.
- **Verify Streamlit changes in a real browser**, not just `AppTest` — this session found two
  defects only by looking (verdict columns clipped off-screen; an arbitrary "largest change from").
- **Wording rules for claims**: no top-N number and no results in report text yet; no
  "hotspots" for the resolution test; no "first"/"gap" claims; the bands are validation-based,
  **not** statistically calibrated (coverage never tested) — don't call them calibrated.
