## What this project is

NUS-ISS Practice Module (Graduate Certificate in Pattern Recognition
Systems). A pattern-recognition system that fuses Landsat thermal +
Sentinel-2 multispectral + Singapore open geospatial/demographic data
into a validated, calibrated **cooling-priority score per URA planning
subzone** — decision support for prioritizing urban cooling
interventions (greening, shading, materials). Positioned explicitly
against Cooling Singapore's UHV work (cited, not claimed as an empty
gap). Four claimed contributions: **C1** data-driven (PCA) score
weighting vs. equal-weight baseline, **C2** a learned predictive heat
model enabling counterfactual queries, **C3** multi-sensor LST
downscaling (30m→10m), **C4** season-controlled temporal composites.

Pipeline stages per the original proposal: **S1** ingest/composite,
**S2** LST downscaling, **S3** land-cover classification (RF+U-Net
ensemble), **S4** unsupervised hotspot clustering, **S5** predictive
heat model (XGBoost+CNN, counterfactuals), **S6** cooling-priority score
construction, **S7** the runnable Streamlit system.

## Where the code lives now

The project was migrated off Colab notebooks into a maintained
structure. **The notebooks under `notebooks/Colab Notebooks/` are
historical reference only — do not treat them as the current
implementation.** The real code:

```
config/settings.py       — single source of truth for every constant
src/utils/                — caching, geo helpers, seeding
src/ingest/                — GEE auth + Landsat/S2/subzones/WorldCover/NEA/SingStat fetchers (S1)
src/downscaling/variants.py — the 3 LST variants (S2, C3)
src/landcover/              — RF + U-Net (S3 — no ensemble/formal eval yet)
src/priority_score/         — pillars + PCA/equal-weight score construction (S6, C1)
src/hotspots/, src/heat_model/  — EMPTY, S4/S5 not built yet
validation/input_validation/    — NEA held-out, land-change, labeling sample/agreement, season window
validation/score_validation/    — rank-impact ablation, heat-variant diagnostic
scripts/                    — 12 CLI entry points, one per pipeline stage
app/                        — Streamlit: Home.py (status page) + the validation-labeling tool (S7 partial — not the real app yet)
```

No packaging — everything runs via `sys.path` manipulation at the top of
each script, repo root on the path. See `SETUP.md` for full environment
setup (GEE service account, `.env`, dependencies).

## Conventions to know before touching this code

- **`config/settings.py` is the only place constants should live.** If
  you're about to hardcode a season window, CRS, threshold, or dataset
  ID somewhere else, it probably already exists there.
- **Caching pattern**: any expensive fetch/compute should check if its
  output already exists locally before redoing the work (see
  `src/utils/caching.py::load_or_fetch` and how every `scripts/*.py`
  checks its own output file first).
- **GEE auth is service-account only** in the migrated code
  (`src/ingest/gee.py::init_ee()`) — no interactive `ee.Authenticate()`
  anywhere in `src/`/`scripts/`/`app/`.
- **Placeholder formulas are marked, not resolved**: NDVI vegetation
  threshold (0.35), the 50/50 sensitivity population/elderly split — both
  explicitly flagged in `config/settings.py` as open S6 decisions, not
  bugs to silently "fix."
- **Windows/WSL split**: the main pipeline runs natively on Windows; only
  U-Net training needs WSL2's GPU. `GEE_PRIVATE_KEY_PATH` needs a WSL-style
  path override when running from there (see `PROGRESS_LOG_2026-07-29_1336.md` §3).
