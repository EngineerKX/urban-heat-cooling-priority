## What this project is

NUS-ISS Practice Module (Graduate Certificate in Pattern Recognition
Systems). A pattern-recognition system that fuses Landsat thermal +
Sentinel-2 multispectral + Singapore open geospatial/demographic data
into a validated, calibrated **cooling-priority score per URA planning
subzone** — decision support for prioritizing urban cooling
interventions (greening, shading, materials). Positioned explicitly
against Cooling Singapore's UHV work (cited, not claimed as an empty
gap). Four claimed contributions, **all four now implemented**: **C1**
data-driven (PCA) score weighting vs. equal-weight baseline, **C2** a
learned predictive heat model (XGBoost + CNN) enabling counterfactual
queries, **C3** multi-sensor LST downscaling (30m→10m), **C4**
season-controlled temporal composites.

Pipeline stages per the original proposal, **all seven now built**: **S1**
ingest/composite, **S2** LST downscaling, **S3** land-cover classification
(RF+U-Net ensemble), **S4** unsupervised hotspot clustering, **S5**
predictive heat model with counterfactuals, **S6** cooling-priority score
construction (with calibrated confidence bands), **S7** the runnable
Streamlit system. This is the first point in the project where every
pipeline stage has real, run-against-real-data code behind it — what's
left (see below) is polish, write-up, and optional extensions, not core
gaps.

## What's done and verified working (not just written — actually run)

Everything from the 2026-08-04 0237 snapshot, plus (all built and
verified against real data in the 2026-08-04 evening session — full
numbers and methodology in `Progress_Log_2026-08-04_1929.md`):

- **Land-cover ensemble wired into the adaptive-capacity pillar.**
  `src/landcover/zonal.py` (new categorical zonal-stats helper) +
  `src/priority_score/pillars.py::build_adaptive_capacity_pillar_landcover`.
  Spearman(NDVI proxy, land-cover ensemble) = **0.953** on real data — the
  two sources agree strongly. `config.settings.ADAPTIVE_CAPACITY_SOURCE`
  selects which one is canonical; both stay computed for comparison.
- **S4 — unsupervised hotspot-typology clustering, built.**
  `src/hotspots/{features,cluster}.py`. Dry/wet seasonal LST+NDVI+NDBI
  features (new `WET_SEASON_MONTHS`, checked against real Landsat scene
  counts before locking); K-means (k=4, silhouette=0.342) chosen over GMM
  (k=3, silhouette=0.297); land-cover-fraction coherence check (features
  never used for clustering) found the hottest cluster is also the most
  built-up, but the least-vegetated cluster is a *different*, cooler
  cluster — explained by high water proximity, a genuine physical finding.
  "Day/night typologies" from the spec explicitly descoped (documented
  limitation: Landsat is daytime-only, NEA has no per-reading timestamps).
- **S5 — XGBoost + CNN predictive heat model with counterfactuals (C2),
  built.** `src/heat_model/{tabular,cnn_patches,counterfactual}.py`.
  XGBoost (subzone-level, target `lst_native30`): test R²=0.80,
  RMSE=1.03°C. CNN (patch-level, target `lst_bicubic10`, reuses U-Net's
  already-downloaded inference patches): val RMSE≈4.9°C. Counterfactual
  mechanism (rasterize edit region → overwrite spectral channels with the
  target class's mean feature vector → re-infer) cross-checked on 3 real
  high-priority subzones (TUAS NORTH, GUL CIRCLE, CHIN BEE) — XGBoost and
  CNN agreed on cooling direction every time. XGBoost and CNN are
  deliberately not soft-voted (different granularities) — they cross-
  check each other instead. CNN training needs WSL2 GPU, same as U-Net.
- **S6 — calibrated confidence bands, built.**
  `validation/score_validation/confidence_bands.py`. Bootstrap (1000
  iterations) using NEA-heldout RMSE (exposure) + land-cover ensemble
  recall binomial SE (adaptive capacity) as noise models — not an
  arbitrary Monte Carlo. Important documented finding: exposure RMSE
  (11.64°C) mixes real noise with the systematic LST-vs-air-temperature
  offset, so bands are a **pessimistic upper bound**, not a tight
  calibrated interval — stated explicitly, not glossed over. Real
  consequence: 19/19 adjacent pairs in the top-20 ranked subzones have
  overlapping bands at this noise level. Sensitivity pillar deliberately
  left unperturbed (no validation-error estimate exists for it).
- **ESA CCI/MODIS LST secondary cross-check, built.**
  `src/ingest/gee.py::fetch_modis_lst_collection`,
  `validation/input_validation/modis_heldout.py`. MODIS chosen over ESA
  CCI. Real result: 99.1% subzone coverage (vs. NEA's sparse ~6%),
  RMSE=6.5°C (lower than NEA's 11.6°C — expected, same physical quantity
  as Landsat), Spearman=0.443 across all 3 LST variants.
- **S7 — the actual runnable app, built.** `app/pages/2_Island_Map.py`
  (folium choropleth, click-to-select working), `3_Subzone_Breakdown.py`
  (plotly pillar/confidence-band/land-cover charts, reloads the real
  production `build_score()` rather than re-deriving it), 
  `4_Counterfactual_Greening.py` (live XGBoost slider + precomputed CNN
  example gallery — native Windows TensorFlow is confirmed broken, so the
  CNN can't run live from the app), `5_Validation_Dashboard.py` (renders
  every validation artifact on disk, not just a checkmark). Verified via
  `tests/test_app_pages.py` (`AppTest`, all 6 pages) **and** an actual
  Playwright browser walkthrough with real screenshots — which caught a
  real UX bug (`st.metric`'s default delta color is backwards for a
  temperature-decrease-is-good context) that no automated test would have.
- **Land-change diagnostic run** (pre-existing script, not built this
  session, just executed on request): 286 stable / 46 flagged (13.9%) of
  332 subzones — `data/interim/land_change_flags.csv`.
- Everything from the prior snapshot remains true: Week-1 gates G1-G5
  pass, RF/U-Net/ensemble land-cover (79.8% ensemble accuracy), heat
  variants for all 332 subzones, MLflow tracking (now also covering S5's

## Conventions to know before touching this code

Everything from the prior snapshot still holds (`config/settings.py` is
the only place constants live; the two caching flavors — plain
file-existence and content-fingerprint; GEE service-account-only auth;
placeholder formulas marked not resolved; the Windows/WSL2 split; GEE's
classifier-capability and export-masking quirks; don't trust a
"placeholder" comment without checking the data; no pytest). New this
session:

- **`scripts/` has no `__init__.py` and scripts never import from each
  other** — shared logic that multiple scripts need belongs in `src/` or
  `validation/`. Found while building S5 (a helper briefly lived in one
  script, got relocated to `src/heat_model/cnn_patches.py` before shipping).
- **XGBoost's categorical encoder breaks on a column cast through pandas'
  nullable `Int64` extension dtype before `.astype("category")`** —
  raises `TypeError: object of type 'int' has no len()`. Cast via plain
  `int` first. A unit test using a plain numpy int array won't catch this
  (it never goes through the `Int64` intermediate) — worth building test
  fixtures the same way the production code path actually constructs data.
- **`src/utils/geo.py::zonal_mean` returns a NaN row (not a dropped row)**
  for any subzone with no valid pixel in-mask. Callers feeding the result
  into something with no NaN tolerance (e.g.
  `sklearn.metrics.mean_squared_error` via `rank_impact.rmse_vs_heldout`)
  must dropna first — `nea_heldout.py` never hits this (built from a
  groupby of only real readings), `modis_heldout.py` does and handles it
  explicitly.
- **A UI/Streamlit change isn't verified by `AppTest` alone** — it checks
  "doesn't crash," not "looks/works right" or "the color semantics are
  correct." Always also launch the real dev server and look at an actual
  screenshot (Playwright works fine in this environment; no `chromium-cli`
  available) before calling a UI change done. `st.metric`'s default delta
  color (green=up/red=down) is backwards whenever the metric is something
  you want to go down — pass `delta_color="inverse"`.
