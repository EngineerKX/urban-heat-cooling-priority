## What this project is

NUS-ISS Practice Module (Graduate Certificate in Pattern Recognition
Systems). A pattern-recognition system that fuses Landsat thermal +
Sentinel-2 multispectral + Singapore open geospatial/demographic data into
a validated, calibrated **cooling-priority score per URA planning
subzone** — decision support for prioritizing urban cooling interventions
(greening, shading, materials). Positioned explicitly against Cooling
Singapore's UHV work (cited, not claimed as an empty gap). Four claimed
contributions, all four implemented: **C1** data-driven (PCA) score
weighting vs. equal-weight baseline, **C2** a learned predictive heat
model (XGBoost + CNN) enabling counterfactual queries, **C3** multi-sensor
LST downscaling (30m→10m), **C4** season-controlled temporal composites.
Seven pipeline stages, all built: **S1** ingest/composite, **S2** LST
downscaling, **S3** land-cover classification (RF+U-Net **hybrid** — see
below), **S4** unsupervised hotspot clustering, **S5** predictive heat
model with counterfactuals, **S6** cooling-priority score construction
(with calibrated confidence bands), **S7** the runnable Streamlit system.

**Grading-rubric note**: the project must demonstrate ≥3 of {supervised/
unsupervised learning, ML/DL, hybrid ML/ensemble, intelligent sensing}.
Confirmed aligned this session — see
[`Progress_Log_2026-09-18_2146.md`](Progress_Log_2026-09-18_2146.md) §9.
Supervised+unsupervised, ML+DL, and hybrid are all unambiguous; intelligent
sensing is a plausible bonus (multi-satellite data fusion) but not needed
to hit the minimum.

## What's NOT done — the actual remaining work

1. **U-Net has zero recall on the "bare" land-cover class** (`bare_f1 =
   0.000` in the current formal evaluation) — a real, checkable finding,
   not noise. Root cause discussed at length this session: the 300-point
   validation set only has 11 "bare" points (3.7%), and training data is
   almost certainly similarly thin for that class — genuine scarcity
   (bare land in Singapore is mostly transient construction sites), not a
   labeling mistake. Recommended next experiment (not yet tried):
   class-weighted loss in `unet_train.py`/`cnn_train.py` — cheap to test,
   would tell you whether the signal exists and is just being outweighted,
   or whether more/better labels are the real lever. The RF+U-Net hybrid
   already compensates for this in practice (bare F1 recovers to 0.417),
   which is worth keeping in mind before spending effort "fixing" U-Net
   alone if the hybrid is what ships.

## Conventions to know before touching this code

Everything from the prior snapshots still holds (`config/settings.py` is
the only place constants live; plain-file-existence + content-fingerprint
caching; GEE service-account-only auth; placeholder formulas marked not
resolved; no pytest; `scripts/` never import from each other; every
training/build script expected to log to MLflow). **Updated or new this
session**:

- **Tensors are channels-last now (`N, H, W, C`), not channels-first.**
  The PyTorch-era convention is gone — if you find old notes/diagrams
  assuming `(N, C, H, W)`, they're describing the previous framework, not
  current code.
- **`.keras` is the save format, not `.pt`.** `state_dict`-style loading
  (`load_state_dict`, reconstructing the architecture before loading
  weights) is gone — `tf.keras.models.load_model(path)` returns a fully
  reconstructed, ready-to-use model in one call. `load_unet()`/
  `load_cnn_regressor()` signatures were simplified accordingly (no more
  `in_channels`/`base_filters` kwargs).
- **"Hybrid," not "ensemble," for the RF+U-Net combination** — this is a
  real naming convention now enforced throughout the codebase, not just a
  one-off rename. If you add new code that touches this combination, name
  it `hybrid`, not `ensemble` — `git grep -i ensemble` should only ever
  turn up `sklearn.ensemble` (a different, correctly-named thing — RF's
  own bagged trees genuinely are a same-model-type ensemble) and the
  deliberate "why hybrid not ensemble" explanations in
  `src/landcover/hybrid.py`'s and `docs/model_training_explained/06_*`'s
  docstrings.
- **`CNN_*` and `UNET_*` hyperparameter constants are independent now**,
  not one shared block — they currently hold identical values by
  coincidence, not by reference. Tune one without worrying about silently
  affecting the other.
- **A repeated identical Windows `pip install` failure inside a deeply
  nested package path (`...\include\external\...`) is a long-path issue,
  not a framework-specific one.** The fix is a one-time OS-level change
  (`LongPathsEnabled` registry key + `git config core.longpaths true` +
  reboot), not something to chase by switching dependencies.
- **A Colab `ImportError` for a symbol you just added to `config/settings.py`
  usually means it hasn't been pushed yet** (Colab clones fresh from
  GitHub every session) — but if it persists *after* confirming the push
  landed (`!git -C {REPO_DIR} log -1 --oneline`), the next suspect is
  Python's own import cache: a full Colab runtime restart, not just
  re-running the repo-sync cell, is what actually picks up new module
  contents in an already-running kernel.
