## 0. How the session started

A factual check of the report paragraph on the validation data. Verified: 300
points, a Streamlit labelling tool on Esri imagery, class + confidence +
"uncertain" flag, 15 m exclusion buffer around every point, kappa 0.676 on a
20-point two-labeller trial. Corrections given: "weighted towards vegetation"
is true of the sampling only (WorldCover-vegetation stratum 186/300, doubled by
an undocumented 2x boost in `allocate_sample_sizes`; hand labels came out 160
built-up / 107 vegetation); the 300 have one agreed label each, not two
independent sets (docs overstate this); "never test on data seen" should say
the exact pixels are excluded. Also answered: WorldCover is itself a model
product and training on it and grading on it would be circular; U-Net is
per-pixel classification with spatial context; the heat typology is
descriptive (silhouette 0.34, top 20 fall in two of four groups); the priority
score combines exposure, sensitivity and greenery deficit.

## 1. Is WorldCover out of date, and is Dynamic World better?

`scripts/compare_worldcover_dynamicworld.py` (commit `43d1c6e`, doc
`docs/dynamic_world_vs_worldcover_2026-09-27.md`). Dynamic World on both sides,
4 classes, 18-month windows around 2021 and 2025–26:

- Land change: 12.5% of pixels changed class vs a 7.0% noise floor; net
  vegetation 30.8% → 32.1%; no top-20 subzone changed by more than 15%. The
  2018–20 vs 2022–24 diagnostic that already existed compares Dynamic World
  with itself and never tested WorldCover's age.
- Agreement with the 300 hand labels, area-weighted: **WorldCover 69.5%**
  (65–74) vs **Dynamic World 81.9%** (77–86) / 85.5% recent. Only ~19% of
  WorldCover's disagreements are explained by change since 2021; the main
  problem is WorldCover calling built-up land vegetation.

## 2. Retraining on Dynamic World (trial models, open label window)

RF 65.6% → 72.6%, U-Net 70.3% → 83.1% (bare F1 0.000 → 0.593), hybrid 69.6% →
81.8%. Two bugs found and fixed on the way (`92b0f09`, `8d05700`):
`parse_training_patches` hard-coded the `wc_class` band; and the U-Net
training-patch GCS cache was keyed only on the validation CSV, so a Dynamic
World run would have silently reused WorldCover patches —
`training_fingerprint` now takes a `label_source` salt. Note: the trial U-Net
notebook ran on the local CPU, not Colab (kernel not selected), which did not
affect correctness.

## 3. Why the hybrid lost to U-Net, and trying to improve RF

Paired check: the hybrid got 6 points wrong that U-Net got right, and 2 the
other way; RF was wrong in the same direction in all 6. A U-Net blend-weight
sweep was monotonic (any RF weight lowers accuracy). The hybrid helped under
WorldCover only because U-Net had a total bare-class blind spot. RF
experiments (`f698522`): post-hoc majority smoothing of RF's output
(diagnostic sweep up to 21x21 was compared on the validation points, so only a
fixed 3x3 = 30 m window is admissible); neighbourhood texture features
(mixed, within noise); smoothed-RF hybrid (worse). User chose to keep the
simple 3x3 smoothing; later (§10) its gain stopped being significant.

## 4. Does the land-cover choice change the priorities?

WorldCover hybrid → Dynamic World hybrid changes 6 of the top 20 (residents
view), rank correlation 0.966; mean greenery per subzone 28% → 12.5%. U-Net vs
hybrid changes 1 of 20. Both within the noise floor. The label-source switch is
the step with the largest decision impact; everything after it barely moves
the ranking.

## 12. Greening what-if fixed (`00283d1`)

Re-measured on the current model, the subzone what-if was noise: +15 pts
vegetation cooled only 56% of subzones (median −0.10 °C, 44% warmer). Cause:
the edit raised vegetation and NDVI but left NDBI, XGBoost's second feature,
unchanged. Fix: `fit_index_landcover_model` fits each of NDVI/NDBI (dry, wet)
on the land-cover fractions and the edit moves all four. Criteria were set
before seeing results: **89% cool, median −0.99 °C**; 1.8% of edited subzones
fall outside the range of real ones (5% for real subzones). Size matches the
cross-subzone association (−1.1 to −1.2 °C per +15 pts). Cross-check now 3/3.
Still association-based, so results stay "indicative, not forecasts".
