## 1. The real gap: hotspot clustering had zero MLflow logging

`scripts/build_hotspot_clusters.py` builds both K-means and GMM, sweeps
k=2..8, compares them, and prints everything to console — but never once
called `mlflow.start_run()`. Every other trainer in the pipeline (RF,

## 3. A real, reproducible GEE timeout — found and fixed

Retraining RF (`train_landcover_rf.py --with-probabilities`) failed twice
in a row, identical stack trace both times:

```
googleapiclient.errors.HttpError: <HttpError 400 ... "Computation timed out.">
...
File "src/landcover/rf_baseline.py", line 198, in informal_accuracy_check
    sampled_records = sampled.getInfo()["features"]
```

Root cause: `informal_accuracy_check()` is the *first* place in `main()`
that actually evaluates the classified image — its
`sampleRegions(...).getInfo()` forces GEE to synchronously compute the
entire upstream lazy graph (Sentinel-2 fetch → cloud mask → median
composite → spectral indices → classify) just to pull ~198 point values,
using `tileScale=4`. Made worse by `--with-probabilities`, which forces
`effective_asset_cache=False` (no cached classifier to skip the graph
with) — confirmed in the log ("RF trained" ran fresh both times, not from
the asset cache).

Same failure twice ruled out plain transient server load. The fix:
`extract_training_samples()`'s `stratifiedSample()` — a comparably
expensive operation over the same boundary — already used `tileScale=8`
and succeeded both times. Bumped `informal_accuracy_check()`'s
`sampleRegions()` to match (`tileScale=4` → `8`,
`src/landcover/rf_baseline.py:197`). Third attempt succeeded — both
rasters exported and downloaded, 75.0% informal accuracy (identical to
the pre-fix numbers, since training is deterministic/seeded).

## 6. Smaller clarifications answered along the way

- **Why does RF need to re-export if it already had output?**
  `train_landcover_rf.py::main()` has no skip-if-exists cache at all
  (unlike `build_landcover_ensemble.py`/`build_hotspot_clusters.py`/
  `train_heat_model_xgboost.py`, which all check "does the output exist —
  skip unless `--force`") — every invocation always retrains and
  re-exports. This is why re-running it for a fresh MLflow-logged run
  necessarily also regenerates the raster.
- **What is a raster?** Explained in plain terms (a grid of per-pixel
  values, contrasted with this pipeline's per-subzone CSVs) since the
  distinction matters for understanding what `rf_landcover.tif` vs.
  `hotspot_clusters.csv` each represent.
- **How to check GEE quota** — Cloud Console → APIs & Services → Earth
  Engine API → Quotas (compute/rate limits) vs. the Code Editor's Assets
  tab (storage quota) — explicitly distinguished from §3's timeout, which
  is a synchronous-compute-endpoint issue (400), not a quota rejection
  (which would be 429).
