## What this project is

NUS-ISS Practice Module (Graduate Certificate in Pattern Recognition
Systems). A pattern-recognition system that fuses Landsat thermal +
Sentinel-2 multispectral + Singapore open geospatial/demographic data
into a validated, calibrated **cooling-priority score per URA planning
subzone** — decision support for prioritizing urban cooling
interventions (greening, shading, materials). Positioned explicitly
against Cooling Singapore's UHV work (cited, not claimed as an empty
gap). Four claimed contributions: **C1** data-driven (PCA) score
weighting vs. equal-weight baseline, **C2** a learned predictive heat
model enabling counterfactual queries, **C3** multi-sensor LST
downscaling (30m→10m), **C4** season-controlled temporal composites.

Pipeline stages per the original proposal: **S1** ingest/composite,
**S2** LST downscaling, **S3** land-cover classification (RF+U-Net
ensemble — **now built**, see below), **S4** unsupervised hotspot
clustering, **S5** predictive heat model (XGBoost+CNN, counterfactuals),
**S6** cooling-priority score construction, **S7** the runnable
Streamlit system.

  held-out): built.
- **Production cooling-priority score + PCA/equal-weight ablation
  table**: built (`data/processed/priority_score.csv`).
- **RF/U-Net land-cover classifiers + soft-voting ensemble + formal
  evaluation — all built and run today.** Against a properly
  WorldCover-stratified, fully hand-relabeled 200-point validation set:

  | model | accuracy | macro F1 | weighted F1 | bare F1 (weakest class) |
  |---|---|---|---|---|
  | RF | 75.0% | 0.657 | 0.768 | 0.229 |
  | U-Net | 78.3% | 0.608 | 0.761 | 0.000 |
  | **Ensemble** | **79.8%** | **0.687** | **0.801** | **0.261** |

  The ensemble beat both individual models on every aggregate metric.
  "Bare" (smallest class, spectrally similar to built-up) is the
  consistent weak point across all three, not a labeling artifact —
  confirmed by an independent live check during development (see
  Progress Log #2). Outputs: `data/processed/landcover/{rf,unet,ensemble}_landcover.tif`
  (+ `_prob.tif` probability rasters) and
  `data/processed/landcover/evaluation/` (comparison table, confusion
  matrices, per-class metrics).
- **MLflow experiment tracking** now wraps both training scripts —
  `src/utils/experiment_tracking.py`, local SQLite store (`mlflow.db` +
  `mlruns/`, both gitignored, no server needed). Run `mlflow ui --backend-store-uri sqlite:///mlflow.db`
  from the repo root to browse.
- **Caching** is real and working: re-running any `scripts/*.py` skips
  recompute if its output already exists (`--force` to override). U-Net's
  training-patch and model caches now use content fingerprinting (hash of
  the validation CSV) rather than plain file-existence, so relabeling
  auto-invalidates the right things without a flag, and hyperparameter-only
  reruns against unchanged labels reuse the cache for free.

## Conventions to know before touching this code

- **`config/settings.py` is the only place constants should live.** If
  you're about to hardcode a season window, CRS, threshold, or dataset
  ID somewhere else, it probably already exists there.
- **Caching pattern**: any expensive fetch/compute should check if its
  output already exists locally before redoing the work. Two flavors in
  this repo now: plain file-existence (`src/utils/caching.py::load_or_fetch`,
  most of `scripts/*.py`), and content-fingerprint-based
  (`src/landcover/unet.py`'s patch/model caches — re-derives automatically
  when the underlying validation CSV changes, not just on a `--force` flag).
- **GEE auth is service-account only** in the migrated code
  (`src/ingest/gee.py::init_ee()`) — no interactive `ee.Authenticate()`
  anywhere in `src/`/`scripts/`/`app/`.
- **Placeholder formulas are marked, not resolved**: NDVI vegetation
  threshold (0.35), the 50/50 sensitivity population/elderly split — both
  explicitly flagged in `config/settings.py` as open S6 decisions, not
  bugs to silently "fix."
- **Windows/WSL split**: the main pipeline (including RF, which trains
  via GEE server-side) runs natively on Windows; only U-Net
  training/inference needs WSL2's GPU (native Windows TensorFlow doesn't
  work at all in this repo's `.venv` — confirmed broken, not just
  GPU-less). `GEE_PRIVATE_KEY_PATH` needs a WSL-style path override when
  running from there.
- **GEE classifiers lose capabilities once round-tripped through an
  asset.** A classifier reloaded via `ee.Classifier.load()` (the normal
  caching path) only supports `CLASSIFICATION` output mode — switching to
  `MULTIPROBABILITY` requires a classifier trained fresh in the current
  session. Found the hard way; see Progress Log #1.
- **GEE exports mask differently by dtype.** Pixels outside a `.clip()`
  boundary come back as `NaN` in float32 bands but `0` in integer bands
  when exported to GeoTIFF — don't assume `0`/`nodata` are interchangeable
  across a repo that mixes both (RF's probability rasters vs. hard-label
  rasters are a real example of this exact trap). See Progress Log #10.
- **Don't trust a "placeholder"/"not yet real" comment without checking
  the actual data it's attached to.** Two separate incidents today
  (Progress Log #7 by omission, #11 directly) came from comments that
  were simply wrong about whether something was real. Cheap to verify,
  expensive to propagate.
- **No pytest in this repo.** Test-like verification lives in `tests/` as
  plain runnable scripts with `assert` + printed PASS/FAIL, matching the
  rest of the codebase's style — not a deliberate rejection of pytest,
  just what was already established when this need first came up.
