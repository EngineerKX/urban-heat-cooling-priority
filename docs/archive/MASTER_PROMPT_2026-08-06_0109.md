## What this project is

NUS-ISS Practice Module (Graduate Certificate in Pattern Recognition
Systems). A pattern-recognition system that fuses Landsat thermal +
Sentinel-2 multispectral + Singapore open geospatial/demographic data into
a validated, calibrated **cooling-priority score per URA planning
subzone** — decision support for prioritizing urban cooling interventions
(greening, shading, materials). Positioned explicitly against Cooling
Singapore's UHV work (cited, not claimed as an empty gap). Four claimed
contributions, all four implemented: **C1** data-driven (PCA) score
weighting vs. equal-weight baseline, **C2** a learned predictive heat
model (XGBoost + CNN) enabling counterfactual queries, **C3** multi-sensor
LST downscaling (30m→10m), **C4** season-controlled temporal composites.
Seven pipeline stages, all built: **S1** ingest/composite, **S2** LST
downscaling, **S3** land-cover classification (RF+U-Net ensemble), **S4**
unsupervised hotspot clustering, **S5** predictive heat model with
counterfactuals, **S6** cooling-priority score construction (with
calibrated confidence bands), **S7** the runnable Streamlit system.

**What changed since the last snapshot**: the entire deep-learning stack
(U-Net land-cover classifier, CNN heat model) was migrated off TensorFlow
onto **PyTorch**, and all training now happens exclusively on **Google
Colab's free GPU** via the official VS Code↔Colab extension — WSL2 is no
longer needed anywhere in this project. This was driven by a practical
need (the project is now being shared with a teammate who has no GPU), not
a methodological change — the models, features, and targets are otherwise
unchanged.

## Conventions to know before touching this code

Everything from the prior snapshot still holds (`config/settings.py` is
the only place constants live; plain-file-existence + content-fingerprint
caching; GEE service-account-only auth; placeholder formulas marked not
resolved; GEE's classifier-capability and export-masking quirks; don't
trust a "placeholder" comment without checking the data; no pytest;
`scripts/` never import from each other). New this session:

- **PyTorch tensors in this repo are channels-first `(N, C, H, W)`**,
  unlike the old TF/Keras code's channels-last convention — this matters
  if you're reading `src/heat_model/counterfactual.py` or any of the
  `*_data.py`/`*_infer.py` modules expecting to find the old `(H, W, C)`
  indexing pattern; it's gone, deliberately, everywhere.
- **`map_location="cpu"` is mandatory on every model load** (`unet_infer.py::load_unet`,
  `cnn_infer.py::load_cnn_regressor`) — weights are always saved from a
  Colab CUDA session, and loading without it breaks the very first
  no-GPU-machine inference attempt. Both loader functions already do this
  correctly; don't add a new load path that skips it.
- **`train_unet()`/`train_cnn_regressor()` default to `force_retrain=False`,
  which silently no-ops if a cached model already exists ON THAT SPECIFIC
  COLAB VM'S DISK** (matching training-data fingerprint) — harmless on a
  genuinely fresh VM, but if you reconnect to/reuse a Colab session from
  an earlier run and want to guarantee a real new training pass, you must
  explicitly flip this to `True` in the notebook cell first. Hit for real
  this session (twice) — see `Progress_Log_2026-08-06_0109.md`.
- **GEE's TFRecord patch export format is still in use** (unchanged by
  the migration — GEE's own export mechanism, not a modeling choice) but
  is now parsed by the pure-Python `tfrecord` package
  (`src/landcover/unet_data.py::read_raw_patches`, one shared reader used
  by training, inference, and the CNN's patch builder — previously
  duplicated 3x as near-identical `tf.io` blocks) instead of `tensorflow`,
  which is fully removed from `requirements.txt`.
- **Don't pin `numpy`/`requests`/`google-auth` in `requirements-colab.txt`**
  — Colab's own preinstalled `google-colab` package needs specific
  versions of these; pinning ours conflicts with it (confirmed via a real
  pip dependency-resolver warning, risked breaking
  `google.colab.files.upload()`/`userdata` specifically).
- **Jupyter shell-magic cells (`!`/`%`) don't reliably inherit a prior
  cell's `os.chdir()`** across cell boundaries in this VS Code↔Colab
  setup — use IPython's `{python_var}` interpolation for absolute paths
  (`%pip install -q -r {REPO_DIR}/requirements-colab.txt`) instead of
  relying on working-directory state carrying over from an earlier
  Python-only cell.
- **`google.colab.files.upload()` doesn't work through VS Code's
  remote-kernel connection to Colab** — hangs indefinitely waiting for a
  browser JS callback that never arrives, since VS Code's notebook
  renderer doesn't implement Colab's custom output-widget bridge. Use
  `getpass.getpass()` instead (standard Jupyter stdin protocol, works
  regardless of frontend) for anything needing masked interactive input
  from a Colab-connected notebook.
- **A validated multi-run comparison beats a single number.** The
  ensemble-not-always-better and ensemble-consistently-below-TF findings
  above only became visible by actually retraining U-Net 3 times and
  formally evaluating each — a single run would have looked like a
  straightforward "PyTorch matches TF" result and missed both findings.
  Worth keeping in mind before treating any single accuracy number in
  this project as final.
