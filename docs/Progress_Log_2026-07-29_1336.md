## 1. Notebook → project migration

All 13 original Colab notebooks (`notebooks/Colab Notebooks/`) were
migrated into a maintained project structure:

- **`config/settings.py`** — single source of truth for every constant
  that used to be copy-pasted across notebooks (AOI, season window, CRS,
  dataset IDs, WorldCover 4-class scheme, seeds, feature bands).
- **`src/utils/`** — `caching.py` (generic fetch-or-load-from-cache
  helper), `geo.py` (normalize, dotted-property sanitizer, zonal-mean
  helper), `seed.py`.
- **`src/ingest/`** — `gee.py` (service-account auth, Landsat/S2
  mask+scale+season-filter helpers, GCS export/download helpers),
  `subzones.py`, `worldcover.py`, `nea.py`, `singstat.py` — each with
  local caching to `data/raw/<source>/`.
- **`src/downscaling/variants.py`** — the 3 LST variants (native30 /
  bicubic10 / regress10).
- **`src/landcover/`** — `rf_baseline.py`, `unet.py`.
- **`src/priority_score/`** — `pillars.py` (sensitivity, adaptive
  capacity), `score.py` (PCA/equal-weight construction).
- **`validation/input_validation/`** — NEA held-out, land-change
  diagnostic, labeling sample generation, labeling agreement (kappa),
  season-window diagnostic.
- **`validation/score_validation/`** — rank-impact ablation test,
  heat-variant diagnostic.
- **`scripts/`** — 12 CLI entry points, one per original notebook,
  orchestration only, importing the modules above.
- **`app/`** — Streamlit entry point + the validation-labeling tool
  (rebuilt from `label_points_interactive.ipynb` using folium +
  streamlit-folium instead of Colab's ipyleaflet widget).

Design decisions made during migration:
- No `pyproject.toml`/packaging — plain scripts, repo root on `sys.path`.
- GEE auth via service account (non-interactive), not the notebooks'
  interactive `ee.Authenticate()`.
- Original notebooks kept untouched under `notebooks/Colab Notebooks/`
  as historical reference, not deleted.

## 2. Bugs found and fixed (roughly in the order hit)

| # | Bug | Fix |
|---|---|---|
| 1 | `requirements.txt` was UTF-16-encoded (PowerShell `>` redirection artifact) — unreadable/corrupted-looking | Re-saved as UTF-8 |
| 2 | `S2_CLOUD_PROB_MAX` drifted: `40` in one notebook, `70` in three others | Consolidated to `70` in `config/settings.py` |
| 3 | `jsonschema-specification` in `requirements.txt` isn't a real PyPI package | Fixed to `jsonschema-specifications` (plural) |
| 4 | `geemap` unconditionally imports the full Jupyter widget stack (ipyleaflet, bqplot, anywidget) — failed to install on Windows (long-path limit, >260 chars) | Dropped entirely; replaced its 2 call sites with `download_small_image()` (via `getDownloadURL`) and `export_geotiff_to_gcs()` (via Cloud Storage) in `src/ingest/gee.py` |
| 5 | Windows console (cp950 codepage) crashed printing ✅/⚠️ emoji | `config/settings.py` reconfigures `sys.stdout`/`stderr` to UTF-8 on import — fixes it everywhere at once |
| 6 | `.env.example` briefly had real credentials copied into it (should be a blank template) | Caught before commit, restored to placeholders |
| 7 | GEE service account got `USER_PROJECT_DENIED` — "Earth Engine Resource Writer" role alone isn't sufficient | Also granted **Service Usage Consumer** at the project IAM level |
| 8 | GCS raster export failed: `storage.objects.create` denied | Granted the service account **Storage Object Admin** on the export bucket specifically |
| 9 | `google-cloud-storage`'s `Client()` doesn't reuse Earth Engine's service-account credentials — looked for Application Default Credentials (`gcloud` login) that don't exist here | Added `_gcs_client()` helper in `src/ingest/gee.py` that explicitly loads the same service-account key file |
| 10 | On WSL2, `blob.download_to_filename()` failed with `PermissionError` — its internal `os.utime()` call isn't supported on the Windows-mounted filesystem (`/mnt/c/...`) | Switched to `client.download_blob_to_file(blob, f)` with a manually-opened file handle (skips the `utime` call) in both GCS download call sites |
| 11 | GCS-exported TFRecord mixer/metadata file is named `{prefix}.json`, not `{prefix}mixer.json` (the Drive-export convention the original notebook assumed) | Fixed the glob pattern in `run_inference_and_reconstruct()` to `*.json` |
| 12 | `wc_class` band exported as an opaque `bytes_list` blob instead of a flat `float_list` array in TFRecord patches — because it was an integer type while every other band was already float, and GEE encodes each band based on its own pixel type | Added `.toFloat()` in `build_training_stack()` so every band encodes uniformly |
| 13 | U-Net's reconstructed raster had 0% nodata and 55.6% "water" — per-patch CNN inference has no notion of "outside the mask" (unlike RF's `classify()`, which carries EE's input mask through automatically); the model defaulted blank/padding-area input to "water" | `run_inference_and_reconstruct()` now takes `boundary` and masks the output raster against it post-reconstruction, matching RF's behavior |

## 4. Pipeline execution status (real runs, real output)

All of the below have been run end-to-end against real Earth Engine /
NEA / SingStat data, not just written and left untested:

- **Week-1 gates** (`scripts/run_week1_gates.py`): G1-G5 all PASS on real
  data. G5's `member_a_labels`/`member_b_labels` were mislabeled in a
  comment as placeholders, but are actually the real independently-
  collected joint-labeling values from `urban_heat_sg_week1_gates.ipynb`
  (kappa=0.676, substantial agreement per Landis & Koch, 17/20 = 85% raw
  agreement, 20 shared points). Confirmed identical to the notebook's own
  arrays and reproduces the same kappa. Comment corrected 2026-08-04.
- **Heat variants** (`scripts/build_heat_variants.py`): 332 subzones, all
  3 LST variants, zero nulls.
- **All 3 pillars** built: sensitivity (332/332 matched), adaptive
  capacity (332/332), NEA held-out (12/332 — expected, sparse station
  coverage).
- **Production priority score** (`scripts/build_priority_score.py`):
  built, PCA + equal-weight ablation tables saved. Top of the list:
  Little India, Loyang West, Tuas North, China Square, Kampong Glam.
- **RF land cover** (`scripts/train_landcover_rf.py`): trained, classifier
  cached as a GEE asset. Superseded 2026-08-04 (see below) — the 72.5%
  informal-accuracy figure previously here was against the pre-relabeling,
  unstratified 200-point sample.
- **U-Net land cover** (`scripts/train_landcover_unet.py`): trained on
  GPU, boundary-masked raster written to
  `data/processed/landcover/unet_landcover.tif`. Superseded 2026-08-04 —
  the 83.9% (199/200 scored) figure previously here was against the same
  pre-relabeling sample.
- **RF/U-Net/ensemble formal evaluation** (2026-08-04,
  `scripts/evaluate_landcover_classifiers.py`): all three scored
  identically (confusion matrix, per-class precision/recall/F1) against
  the properly WorldCover-stratified, fully relabeled 200-point validation
  set. RF 75.0% accuracy / 0.657 macro-F1 / 0.768 weighted-F1. U-Net
  78.3% / 0.608 / 0.761. Soft-voting **ensemble 79.8% / 0.687 / 0.801** —
  beat both individual models on every aggregate metric, and on 3 of 4
  per-class F1s (tied on water). Weakest class throughout: "bare" (F1
  0.23 RF, 0.00 U-Net, 0.26 ensemble) — smallest class (11 points) and
  spectrally similar to built-up, a known real confusion, not a labeling
  artifact. Ensemble built via `src/landcover/ensemble.py`
  (per-class-probability soft-voting, RF's grid as the alignment
  reference). MLflow experiment tracking
  (`src/utils/experiment_tracking.py`, local SQLite store) added for both
  training scripts.
