## 3. Item 3 — S5 XGBoost + CNN predictive heat model with counterfactuals (C2)

Locked decisions: TensorFlow/Keras for the CNN (matches U-Net, no new
framework); XGBoost predicts `lst_native30` (raw) from subzone tabular
features, CNN predicts `lst_bicubic10` (pure interpolation) from 10m
patches — both targets chosen specifically to avoid circularity against
NDVI/NDBI/NDWI, which are inputs to both models.

- **`src/heat_model/tabular.py`** (new): `build_xgb_training_table` (pure
  join of already-built CSVs — heat variants, S4 hotspot-cluster output
  which already carries land-cover fractions from Item 1, sensitivity
  pillar — no new fetch), `train_xgb_model`, `fit_ndvi_vegetation_slope`,
  `redistribute_vegetation_fraction` (pure fraction-arithmetic core,
  factored out for independent testing), `predict_counterfactual_subzone`.
- **`src/landcover/unet.py`**: refactored `build_unet` into
  `build_unet_backbone()` (the encoder-decoder minus the output head) +
  `build_unet()` (adds the softmax head) — so the new CNN regressor reuses
  the *exact* same architecture rather than duplicating ~25 lines.
- **`src/heat_model/cnn_patches.py`** (new): reuses U-Net's already-
  downloaded inference patches (`data/interim/unet_patches/inference/`) as
  the spatial feature source. The only new GEE work is one full-Singapore
  `lst_bicubic10` GeoTIFF export (`variant_bicubic10`, unmodified).
  `build_local_feature_target_patches()` reads matching windows from the
  ensemble land-cover raster and the new LST raster via
  `rasterio.warp.reproject` onto each patch's own transform (same
  technique `ensemble.py::load_prob_raster` uses for RF-vs-U-Net grid
  mismatches) rather than assuming pixel alignment. `build_cnn_regressor`
  (linear head on `build_unet_backbone`), `train_cnn_regressor`,
  `run_cnn_inference`, `locate_patch_and_pixel` (WGS84 lon/lat → patch
  index + local pixel, shared by two scripts — see bug table).
- **`src/heat_model/counterfactual.py`** (new): the concrete mechanism —
  `class_mean_feature_vectors` (global per-class mean spectral+index
  vector), `apply_patch_counterfactual` (overwrite edited pixels'
  spectral+index channels with the target class's mean vector, keeping
  the edited patch in-distribution for the CNN, plus a clean one-hot
  land-cover flag), `run_patch_counterfactual`, `rescale_subzone_delta`
  (area-weighted extrapolation so the CNN's local delta and XGBoost's
  subzone-level delta can be compared side by side). XGBoost and CNN are
  deliberately **not** soft-voted like RF+U-Net — different granularities,
  built as two independent counterfactual tools that cross-check each
  other's direction/magnitude instead.
- **`src/utils/experiment_tracking.py`**: `start_run()` gained an
  `experiment_name` kwarg (default unchanged — zero blast radius on the
  existing RF/U-Net training scripts); new
  `HEAT_MODEL_EXPERIMENT_NAME = "heat_model_s5"`.
- **`scripts/train_heat_model_xgboost.py`** (new, native Windows).
- **`scripts/train_heat_model_cnn.py`** (new, WSL2 — exports
  `lst_bicubic10_full.tif`, builds local feature/target patches, trains).
- **`scripts/run_counterfactual.py`** (new) — CLI query tool
  (`--subzone-id`, `--delta-vegetation`, optional `--lon/--lat/--radius-m
  --target-class` for the patch-level path). No `--force` — a query tool,
  not a build-once cache.
- **`scripts/diagnose_heat_model.py`** (new) — side-by-side metrics +
  counterfactual cross-check on 3 real high-priority subzones (TUAS NORTH,
  GUL CIRCLE, CHIN BEE), saves `canned_counterfactual_examples.json` for
  S7's counterfactual page (native Windows can't run the CNN live).
- **`tests/test_heat_model_tabular.py`**, **`test_heat_model_counterfactual.py`**
  (new) — synthetic data, no TensorFlow/GEE required.

**Real results:**
- **XGBoost**: test RMSE=1.034°C, R²=0.800 (n_train=265, n_test=67).
  Feature importances: `fraction_built_up` (0.374) and `primary_cluster`
  (0.349) dominate, then `ndbi_dry` (0.122).
- **CNN**: trained 30 epochs (early-stop patience=5, didn't trigger within
  30 epochs but `restore_best_weights=True` kept the best checkpoint),
  best val_loss (MSE)=9.467 at epoch 25 → val RMSE≈4.89°C. 906 train / 160
  val patches from 1066 total (40.9% valid pixels of 17,465,344 — the
  rectangular patch grid includes a lot of open sea).
- **Counterfactual cross-check** (+0.15 vegetation fraction,
  same-direction check on real subzones): TUAS NORTH −1.014°C (XGBoost) vs.
  −2.843°C (CNN, local); GUL CIRCLE −1.049°C vs. −2.819°C; CHIN BEE
  −0.223°C vs. −4.491°C. **All three agree on cooling direction** — the
  CNN's local effect is consistently larger in magnitude (concentrated in
  a small edited radius) than XGBoost's subzone-averaged effect, which is
  physically sensible, not a discrepancy.
- CLI end-to-end check (`run_counterfactual.py --subzone-id "TUAS NORTH"
  --lon 103.63 --lat 1.327 --radius-m 50`): 81 pixels edited (~8,100 m²),
  mean ΔLST in edit area −1.576°C, naive area-weighted subzone-wide
  equivalent −0.0039°C (edited area is 0.249% of TUAS NORTH).

## 4. Item 4 — S6 calibrated confidence bands

Locked decision: bootstrap using already-built validation error estimates
as noise models, not an arbitrary Monte Carlo over unvalidated input
ranges (e.g. the 0.35 NDVI threshold has no natural uncertainty range).

- **`validation/score_validation/confidence_bands.py`** (new):
  `exposure_noise_std` (NEA-heldout RMSE via `rank_impact.rmse_vs_heldout`,
  reused unmodified), `adaptive_capacity_noise_std` (vegetation-class
  recall binomial SE from the ensemble's own confusion matrix),
  `bootstrap_priority_score` (reuses `build_score` unmodified, B=1000
  perturbed draws, reports p05/p50/p95 quantiles).
- **`src/priority_score/io.py`** (new): `load_and_join`/`make_toy_pillars`
  extracted out of `scripts/build_priority_score.py` so this new script
  doesn't duplicate the pillar-join logic. `build_priority_score.py`
  updated to import from here; verified identical output after the
  refactor.
- **`config/settings.py`**: `PRIORITY_SCORE_BOOTSTRAP_ITERATIONS = 1000`,
  `PRIORITY_SCORE_BAND_QUANTILES = (0.05, 0.50, 0.95)`.
- **`scripts/build_priority_score_confidence_bands.py`** (new) — prints a
  "N/19 adjacent top-20 pairs have overlapping bands" diagnostic.
- **`tests/test_confidence_bands.py`** (new): zero-noise collapses to the
  point estimate; nonzero noise gives monotonic quantiles; larger noise
  gives wider bands; binomial-SE arithmetic checked against a hand-built
  confusion matrix.

**Real result — and an important stated limitation found empirically:**
exposure noise std = NEA-heldout RMSE = **11.64°C**, large relative to
LST's own ~30-50°C range. This mixes genuine random error with the
*systematic* LST-vs-air-temperature offset (NEA measures air temperature,
not LST) — documented explicitly in the module docstring and the script's
printed output as a "pessimistic upper bound, not a tight calibrated
interval," not silently glossed over. Adaptive-capacity noise std=0.0357
(vegetation recall=0.845, n=103). Mean band width (p95−p05)=0.116. Real
consequence: **19 of 19 adjacent pairs in the top-20 ranked subzones have
overlapping bands** — under this noise budget, the top-20 rank ordering
isn't statistically distinguishable. The sensitivity pillar is left
unperturbed throughout (no validation-error estimate exists for SingStat
population data anywhere in this repo) — a second stated limitation.

## 5. Item 5 — ESA CCI/MODIS LST secondary cross-check

MODIS chosen over ESA CCI: better GEE support, full spatial coverage
(complements NEA's sparse coverage), and a genuine LST product (same
physical quantity as Landsat) unlike NEA's air-temperature proxy — at the
cost of coarse 1km resolution vs. subzone scale.

- **`src/ingest/gee.py`**: new `fetch_modis_lst_collection()`
  (`MODIS/061/MOD11A2`, reuses `date_filter_for_years_months` unmodified;
  0 is this product's fill value, masked before the Kelvin×0.02→Celsius
  conversion).
- **`validation/input_validation/modis_heldout.py`** (new): mirrors
  `nea_heldout.py`'s structure/limitations-docstring pattern.
- **`config/settings.py`**: `RAW_CCI_MODIS_LST_DIR` (already-scaffolded
  empty dir from initial repo setup, now used), `MODIS_LST_ASSET`,
  `MODIS_LST_SCALE_M = 1000`.
- **`scripts/build_modis_heldout.py`**, **`diagnose_modis_crosscheck.py`**
  (new) — the latter compares all 3 LST variants against both MODIS and
  NEA side by side (RMSE + Spearman), reusing `rmse_vs_heldout` unmodified.

**Real result:** 329/332 subzones with a valid value (**99.1% coverage**,
vs. NEA's sparse ~6%). RMSE=6.507°C (lower than NEA's 11.64°C — expected,
since MODIS measures the same physical quantity as Landsat rather than
air temperature). Spearman=0.443 across all 3 LST variants — a defensible
positive cross-check despite the 1km-vs-subzone resolution mismatch.

## 8. Post-session: land-change diagnostic run on request

User asked what the Home page's "Land-change flags — not yet built" line
meant. It's a **pre-existing** diagnostic
(`validation/input_validation/land_change.py`, not built this session) —
compares Dynamic World's dominant land-cover class between an early
(2018-01-01 to 2021-01-01) and late (2022-01-01 to 2025-01-01) period per
subzone, flagging subzones where the multi-year heat composite might be
silently blending two different real land-cover states (e.g.
redevelopment). Ran it on request (`python scripts/diagnose_land_change.py`):
64 early-period + 43 late-period Dynamic World images, 7.1% of
22,497,105 valid pixels changed dominant class map-wide, **286 stable /
46 flagged** subzones (13.9%), 0 with insufficient data. Output now at
`data/interim/land_change_flags.csv` and visible on both `Home.py`'s
status list and the Validation Dashboard's "Land-change diagnostic"
section.
