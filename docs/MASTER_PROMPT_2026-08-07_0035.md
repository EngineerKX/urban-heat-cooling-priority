## What this project is

NUS-ISS Practice Module (Graduate Certificate in Pattern Recognition
Systems). A pattern-recognition system that fuses Landsat thermal +
Sentinel-2 multispectral + Singapore open geospatial/demographic data into
a validated, calibrated **cooling-priority score per URA planning
subzone** — decision support for prioritizing urban cooling interventions
(greening, shading, materials). Positioned explicitly against Cooling
Singapore's UHV work (cited, not claimed as an empty gap). Four claimed
contributions, all four implemented: **C1** data-driven (PCA) score
weighting vs. equal-weight baseline, **C2** a learned predictive heat
model (XGBoost + CNN) enabling counterfactual queries, **C3** multi-sensor
LST downscaling (30m→10m), **C4** season-controlled temporal composites.
Seven pipeline stages, all built: **S1** ingest/composite, **S2** LST
downscaling, **S3** land-cover classification (RF+U-Net ensemble), **S4**
unsupervised hotspot clustering, **S5** predictive heat model with
counterfactuals, **S6** cooling-priority score construction (with
calibrated confidence bands), **S7** the runnable Streamlit system.

**What changed since the last snapshot**: no architectural change — this
session closed a real MLflow-coverage gap (S4 hotspot clustering was
never logged), fixed a reproducible GEE timeout bug in RF training, and
retrained every local model (RF, K-means/GMM, XGBoost) so MLflow now has
a real run for *every* trainer in the pipeline, not just the deep-learning
ones. `TRAINING_INSTRUCTIONS.md` (new) documents the full retrain sequence
in actual dependency order.

## Conventions to know before touching this code

Everything from the prior snapshots still holds (`config/settings.py` is
the only place constants live; plain-file-existence + content-fingerprint
caching; GEE service-account-only auth; placeholder formulas marked not
resolved; channels-first PyTorch tensors; `map_location="cpu"` mandatory
on model loads; `force_retrain` same-Colab-session gotcha; no pytest;
`scripts/` never import from each other). New this session:

- **Every training/build script in this pipeline is now expected to log
  to MLflow.** If you add a new trainer or unsupervised-fitting script,
  give it a `start_run(...)` block (see
  `src/utils/experiment_tracking.py`) rather than just printing results —
  `build_hotspot_clusters.py` going unlogged for as long as it did was a
  real, silently-accumulating gap, not a deliberate choice.
- **Most build/train scripts in this repo skip-if-output-exists by
  default** (`build_landcover_ensemble.py`, `build_hotspot_clusters.py`,
  `train_heat_model_xgboost.py` all take a `--force`/`--force-retrain`
  flag) — **except `train_landcover_rf.py`, which has no such check at
  all** and always retrains + re-exports on every invocation. Don't
  assume every script in this repo follows the same caching convention
  without checking its `main()`.
- **A repeated identical GEE `"Computation timed out."` (400 error) is
  not a quota problem** (quota rejections are 429s) — it's GEE's
  synchronous compute endpoint giving up on an expensive lazy graph.
  `tileScale` is the lever, not retrying blindly or checking
  Cloud-Console quota pages. Compare against a sibling call of similar
  cost that already works before assuming it's transient.
- **When asked to "rerun training so MLflow captures it," check for
  cascading dependencies before just rerunning the named script.**
  RF feeds the ensemble; the ensemble feeds hotspot clustering's
  coherence check *and* the CNN's Colab training input; hotspot
  clustering feeds XGBoost's `primary_cluster` feature. A rerun of one
  local trainer can silently invalidate several downstream artifacts —
  worth surfacing the full blast radius (and asking about scope, isolated
  vs. cascade) before just running the one command literally requested.
